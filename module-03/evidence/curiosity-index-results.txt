The equality predicate changed from a table scan to an indexed search. The
leading-wildcard predicate still scanned because an ordinary B-tree cannot use
`%ei%` as a selective prefix range. No timing claim is made: this small
in-memory fixture is intended to demonstrate planner choices, not portable
performance.

Indexes also have a maintenance cost that is not measured by this read-only
query-plan exercise. Inserts, updates to indexed values, and deletes must keep
the index consistent, and the index uses additional storage. This is why an
index should be justified by actual query patterns instead of added to every
column automatically.

# Decision memo to Lea Winter and Yasmin Kaya

Move the two full-history reporting aggregates to a reproducible Parquet copy, while keeping operational writes and point lookups in SQLite. On this machine, the dashboard median fell from 5,832.15 ms in SQLite to 74.13 ms in DuckDB (78.67× faster), with equivalent 350-row results. The monthly report fell from 7,013.05 ms to 74.27 ms (94.43× faster), with equivalent 1,500-row results. The default Parquet file is 2,323,412 bytes, and the validated Zstandard copy is 1,367,276 bytes, 41.15% smaller. Refresh the analytical copy nightly after the last shift by running `prepare.py`, `to_parquet.py`, validation, and then atomically publishing the new Parquet only if its row count, price sum, ID sum, date range, and null checks match. If that refresh fails or becomes a day stale, keep the last validated file, alert the report owner, and label reports with the snapshot timestamp because new jobs and corrections will be missing. Do not move request-per-row work: 1,000 DuckDB inserts and lookups took 6,549.83 ms and 2,710.14 ms, compared with SQLite's 3.30 ms and 4.33 ms, so SQLite remains the operational system of record.
